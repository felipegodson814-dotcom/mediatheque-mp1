# Journal de bord

## Difficultés rencontrées
- Respecter précisément la structure imposée tout en gardant un code propre et lisible.
- Gérer les erreurs sur les paramètres `GET` (`id` et `categorie`) sans faire planter l’application.
- Assurer un rendu visuel moderne avec un thème clair et un thème sombre sans compromettre la simplicité du code.
- Concilier le besoin pédagogique du TP avec les exigences d’ergonomie et de design.

## Solutions apportées
- Créer une architecture de fichiers conforme au sujet et utiliser des includes pour éviter les répétitions.
- Valider les identifiants et les catégories avant affichage, avec messages explicites pour les cas invalides.
- Mettre en place un système CSS clair/sombre et une navigation cohérente sur chaque page.
- Centraliser la logique métier dans `includes/fonctions.php` pour garantir la qualité du code.

## Ce que j’ai appris
- La création d’un projet PHP de manière structurée est fondamentale pour la maintenabilité.
- Les fonctions PHP bien nommées et réutilisées font gagner en lisibilité et en fiabilité.
- Une bonne interface utilisateur repose autant sur des bonnes pratiques de code que sur un design étudié.
- La validation des entrées est indispensable pour éviter les erreurs et sécuriser le site.

> Ce journal est concis et modifiable. Il peut être adapté aux observations propres à chaque session d’essais.
